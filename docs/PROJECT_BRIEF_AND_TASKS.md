# PCB X 光缺陷识别项目简述与任务清单

更新日期：2026-09-16  
当前状态：基础数据整理和三类缺陷 ROI 分类基线已完成；通用焊点切割路线已搁置；等待选择并验证下一条路线。

## 1. 项目目标

本项目面向 PCB X 光图像，目标是建立一套可复用的缺陷识别流程，并最终接入现有 Windows 桌面识别程序。

当前优先处理三类缺陷：

1. 空洞（`void`）
2. 焊点桥连（`bridge`）
3. 透锡不足（`insufficient_through_solder`）

现阶段不追求一次性识别所有板型、元件和拍摄角度。更可行的策略是先固定缺陷类型、元件族和观察视角，完成可量化的最小实验，再逐步扩大适用范围。

## 2. 当前仓库包含什么

### 2.1 应用与训练代码

- `run_app.py`、`screen_recognition_app/`：Windows 截屏识别与透明标注界面。
- `prepare_*_dataset.py`：把现有标注整理为 YOLO 检测或 ROI 分类数据集。
- `train_*`：空洞检测、空洞 ROI 分类及其他缺陷 ROI 分类训练入口。
- `annotate_*`、`categorize_*`：预测可视化和错分样本归档工具。

桌面程序目前可以运行，但默认的 `yolo11n.pt` 是通用 COCO 预训练模型，不是 PCB X 光缺陷模型，因此不能把当前界面效果当作项目最终识别能力。

### 2.2 数据与标注

`pcb_xray_annotation_workspace/images/` 是当前较适合继续实验的去重标注工作区：

- 唯一图像：255 张
- 已发现并排除的完全重复图像：16 张
- 已发现的标签冲突：0 组
- 空洞：112 张
- 桥连：34 张
- 透锡不足：109 张

项目中还存在三种不同的 JSON 标注格式，使用前必须先确认来源，不能直接混合：

1. `pcb_xray_annotation_workspace/images/`：LabelMe 矩形框。
2. `DataV1/数据集/`：自定义缺陷类别和旋转椭圆。
3. `DataV1/数据集2/`：切片级 `image_label` 和对象 `bbox`。

### 2.3 版本管理边界

- JPG/JPEG 和 ZIP 不提交 Git，只保留在本机或独立数据存储中。
- 代码、Markdown、JSON、JSONL、CSV、YAML 和配置文件由普通 Git 管理。
- PT、PNG 等较大二进制文件按现有规则使用 Git LFS。
- 在其他设备克隆仓库后，必须另外恢复本地 JPG 数据，才能重新训练或复查样本。

## 3. 已完成工作

### 3.1 数据整理

- 已建立统一的三类缺陷标注工作区。
- 已完成图像去重、同名参考图匹配和基础标签冲突检查。
- 已建立 ROI 数据生成、训练、评估和错分样本整理脚本。

### 3.2 已有基线结果

| 任务 | 当前结果 | 主要问题 |
| --- | --- | --- |
| 空洞 ROI 二分类 | 最佳验证准确率 0.964 | 负样本以自动随机裁剪为主，真实难负样本不足 |
| 桥连 ROI 二分类 | 测试准确率 0.8435（264/313） | 40 个桥连被判为正常，漏检较明显 |
| 透锡不足 ROI 二分类 | 测试准确率 0.8537（537/629） | 67 个缺陷被判为正常，仍需降低漏检 |

以上结果只能证明“在给定 ROI 内做二分类”具有可行性，不能证明系统已经能够在整张 X 光图上自动找到并识别缺陷。

### 3.3 已搁置路线

此前尝试过基于多行规则圆形焊点阵列的筛选与切割。该路线已搁置，原因包括：

- 不同元件上存在大量外观相似的黑色圆形或柱状结构。
- 不同角度、遮挡和透视会显著改变焊点形态。
- 规则检测容易把阴影或其他部件误认为目标元件。
- 直接对整图做通用焊点切割，标注和验证成本过高。

保留的思路记录见 `docs/ARCHIVED_SOLDER_JOINT_MVP_IDEA.md`。除非获得新的元件定位信息或更明确的数据条件，否则不要恢复“先做通用焊点切割”的旧路线。若以后重启，建议采用“元件定位或检索 → 局部裁剪 → 局部焊点分析”的层级方案。

## 4. 下一阶段总体原则

下一阶段先解决“实验对象不够明确”和“离线结果无法代表整图能力”两个问题。任何新路线开始前，都应先写清楚四项内容：

1. 目标缺陷与目标元件族是什么。
2. 输入是整图、元件区域还是已裁好的缺陷 ROI。
3. 训练集、验证集和测试集如何按原始板件或图像来源隔离。
4. 用什么指标判断路线值得继续。

推荐先选择一个缺陷完成闭环，而不是同时重训三类。当前优先建议从桥连开始，因为它的现有测试准确率最低、漏检问题清晰，且已有错分样本可以直接用于误差分析。最终优先级仍应由实际业务风险决定。

## 5. 任务清单

### P0：确定下一条最小实验路线

- [ ] 用户确认下一阶段优先缺陷：桥连、空洞或透锡不足。
- [ ] 用户确认最重要的业务指标：优先降低漏检，还是优先降低误报。
- [ ] 明确目标元件族和允许的拍摄角度；无法确认的样本单独标为待审核，不强行纳入训练。
- [ ] 固定一份按原始板件或原始图像分组的测试集，禁止同源裁剪块跨训练集和测试集。

验收标准：形成一页实验定义，至少写明目标、输入单位、数据来源、划分方法和主指标。

### P1：审计现有基线与标注

- [ ] 汇总桥连、透锡不足和空洞的现有训练配置、数据量和划分清单。
- [ ] 检查训练集、验证集和测试集之间是否存在重复图、近重复图或同源 ROI 泄漏。
- [ ] 生成现有模型的错分样本联系表或缩略图索引。
- [ ] 优先人工复核桥连的 40 个假阴性和 9 个假阳性。
- [ ] 优先人工复核透锡不足的 67 个假阴性和 25 个假阳性。
- [ ] 将错分原因归类为：标签错误、裁剪范围不当、相似正常结构、图像质量问题、视角问题或模型能力不足。

验收标准：每个错分样本都有可追溯路径和原因类别，并能判断问题主要来自数据、ROI 定义还是模型。

### P2：改进单一缺陷的 ROI 基线

- [ ] 统一目标缺陷的 ROI 裁剪规则，明确框外保留多少上下文。
- [ ] 从真实正常区域和相似元件中补充难负样本，避免只用随机背景块。
- [ ] 清理或隔离有歧义的训练样本。
- [ ] 使用固定测试集重训一个可复现基线。
- [ ] 输出准确率、精确率、召回率、F1、混淆矩阵和逐样本预测清单，不只报告准确率。
- [ ] 对新旧模型使用相同测试集比较，并记录仍然失败的主要场景。

建议的暂定门槛（需要用户根据业务风险确认）：目标缺陷召回率不低于 0.90、精确率不低于 0.85，并且测试集不存在明显同源泄漏。若达不到门槛，应先分析失败原因，不直接扩大模型或批量生成合成样本。

### P3：从 ROI 分类走向整图流程

- [ ] 为目标元件族建立元件定位、模板检索或候选区域生成方法。
- [ ] 将候选元件区域送入已验证的 ROI 分类器。
- [ ] 在整图级别统计漏检、误报和每张图候选数量。
- [ ] 分别测试不同视角、遮挡程度和图像质量，不把它们混成一个平均值。
- [ ] 达到离线指标后，再替换桌面程序中的通用 COCO 模型。

验收标准：输入一张未参与训练的完整 X 光图，系统能够自动产生可追溯的候选区域和缺陷判断，并输出整图级评估结果。

### P4：桌面程序集成与交付

- [ ] 在配置文件中增加 PCB 专用模型与阈值设置。
- [ ] 保留检测框、置信度、时间和原图来源，便于回溯误报。
- [ ] 测试连续截屏时的速度、内存占用和稳定性。
- [ ] 编写运行说明、模型版本说明和已知限制。

验收标准：在目标设备上连续运行稳定，模型版本和阈值可追踪，输出结果能够被人工复核。

## 6. 人工必须完成的事项

以下内容涉及业务定义或真实缺陷判断，不能完全由脚本替代：

- 决定下一阶段最优先的缺陷类型和业务容错方向。
- 确认目标元件族及哪些拍摄角度属于可接受范围。
- 复核模型错分样本和有歧义标注。
- 确认建议指标是否符合实际生产要求。
- 必要时向技术人员确认无法凭图像确定的器件或缺陷。

这些任务不要求手写 JSON 坐标。需要补框或改框时，应优先使用可视化标注工具或项目脚本生成对应文件。

## 7. 可以由 Codex 完成的事项

- 扫描标注清单、检查重复与数据泄漏。
- 生成缩略图索引、错分样本联系表和待审核 CSV。
- 编写或修改可视化标注辅助脚本。
- 整理数据集划分、训练配置和可复现实验命令。
- 训练、评估、对比模型并生成报告。
- 将通过离线验收的模型接入桌面程序。
- 更新项目文档并同步 Git；不提交 JPG/JPEG 和 ZIP。

当任务进行到必须人工判断的节点时，应暂停并给出最小、明确的审核材料，等待用户确认后再继续。
